# Proficiency validation

Validation of controlled vocabulary and syntactic-range rewrites of LURK Werewolf
utterances. The English intervention must preserve game meaning, certainty,
speech-act force, politeness and register while keeping the text grammatical.

Read **[VALIDATION.md](VALIDATION.md)** for the current results and
**[PLAN.md](PLAN.md)** for the validation design.

## Data

| File | Contents |
| --- | --- |
| `data/sources.jsonl` | All 280 untreated public utterances from three game runs, with predicates, speech IDs and prior public history |
| `data/bundles.jsonl` | 24 original passages formed from matched source IDs under the descriptive 150 to 250 word window |
| `data/original_features.jsonl` | Original-only lexical and syntactic measurements, with unavailable measurements left null |
| `data/provenance.json` | Raw-source hashes, recorded models, sampling rule, measurement settings and derived-file hashes |
| `data/report.json` | Recomputed descriptive statistics behind VALIDATION.md |

Raw game logs are stored in `experiments/validation/run01`, `run02` and `run03`.
Git tracks the curated proficiency artifacts and ignores `experiments/validation/`.
The curated artifacts contain the inputs needed to reproduce the source report.

The source games were generated by `deepseek-chat`. The planned validation models
include Qwen3.5 for initial testing and DeepSeek as a candidate for subsequent tests.

## Setup

Run commands from the repository root. Dependencies are declared in
`pyproject.toml`. The proficiency extra includes spaCy, PyTorch and Transformers.

```bash
pip install -e '.[proficiency]'
python -m spacy download en_core_web_sm
```

LanguageTool and SUBTLEX are external measurement resources. Their versions and
file hashes must be recorded before formal validation. The source report is
computed offline from the curated artifacts.

## Commands

Reproduce the statistics in VALIDATION.md from the curated artifacts.

```bash
python -m experiments.proficiency_validation.code.cli report \
    --out experiments/proficiency_validation/VALIDATION.md \
    --json experiments/proficiency_validation/data/report.json
```

Rebuild the curated originals and their measurements from the local raw runs.

```bash
python -m experiments.proficiency_validation.code.cli prepare-data \
    experiments/validation/run01 experiments/validation/run02 experiments/validation/run03
```

This command rejects treated runs, preserves every original utterance, cuts public
history before each source turn, computes the available Original measurements,
and regenerates the source report.

Inspect the English prompts without contacting a model.

```bash
python -m experiments.proficiency_validation.code.cli generate \
    --sources experiments/proficiency_validation/data/sources.jsonl \
    --conditions low,neutral,high --dry-run --out /dev/null
```

Run the offline regression tests.

```bash
python -m unittest discover -s experiments/proficiency_validation/tests
```

## Proficiency validation workflow

Validation combines linguistic measurements, automated fidelity checks and blind
model comparisons. After the generator and independent English judge are selected,
`generate` records each rewrite attempt and failure. `features`, `guardrails` and
`probe` measure the resulting stimuli.

`analyze --no-frozen` is for pilot diagnostics. A formal run requires a complete
protocol with justified thresholds, identified measurement models and disjoint source cohorts.
`freeze` and `verify-frozen` enforce those decisions; all later commands use the same
`--frozen` file and `--split`. Confirmation requires every prespecified criterion
to be evaluated and satisfied.
Command-specific arguments are available through `--help`.

The verdict concerns measured linguistic range and model perception. Generalization
to human perception or overall English ability requires separate evidence.

`generate` and `probe` save row checkpoints and accept `--resume` with unchanged
inputs and settings. Recorded failures are retained on resume. Use one output path
per run.

## Code

| Path | Responsibility |
| --- | --- |
| `code/report.py`, `audit.py`, `bundles.py` | Untreated sources, passage selection and reproducible reporting |
| `code/english_validator.py`, `semantic_gate.py` | English fidelity contract, gating and retry policy |
| `code/generate.py`, `models.py` | Rewrite generation and identified model access |
| `code/features.py`, `guardrails.py`, `listener.py` | Range, grammaticality and perception measurements |
| `code/human_validation.py` | Optional supplementary English annotation tools |
| `code/protocol.py`, `freeze.py`, `frozen.py` | Explicit research decisions and artifact checks |
| `code/analysis.py`, `confirmatory.py` | Statistical comparisons and validation verdicts |
| `tests/` | Offline scientific and implementation regression tests |

The reusable English rewriter is `components/rewriters/language_rewriter.py`.
Metrics and statistics live in `components/metrics/` and `components/stats.py`.
